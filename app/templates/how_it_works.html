From one sentence to a verified application

Every application goes through the same six steps. The model reads the message and words the next question; everything else is code, which is instant, exact and covered by tests.

  1. Read the message

    One model call reads the customer's latest reply, with only the question it answers as context, and returns a forced tool call: the facts stated, the ones that were vague (“about a dozen”), and the ones the customer said they don't know. It is told never to fill in a typical value.

  2. Check it in code

    Pydantic validates every value: real US states (“Texas” becomes TX), sensible numbers, known industries. Then the no-guess rules: “don't know” counts only for the question just asked, a saved answer changes only when we asked about it, and a business name or description must be made of words the customer actually typed.

  3. Pick the next question

    A fixed priority order, plus typed follow-ups for each industry: a roofer is asked roof height and torch-down work, a daycare its licensed capacity and pool. Anything answered, unknown or not applicable is skipped, so most owners answer about seven questions. A second model call only words the chosen question naturally.

  4. Confirm before saving

    Vague numbers are held back and read back to the customer to confirm. When nothing is left to ask, code writes the summary from the validated answers, so it can't misstate anything. The customer approves it or corrects it.

  5. Submit to three carriers

    The submission agent reads each carrier's quote form like any website. The model maps the form's fields to the application, three times independently, and only what most samples agree on is kept and cached; it never sees or writes a value. Code fills every value from the application, takes units from the form's own words (a form that says "thousands" gets dollars / 1000), and stops with "needs info" instead of guessing a missing fact. Quotes, declines and follow-up questions come back side by side.

  6. Coverage and flags by rule

    Suggested policies and hard-to-place flags (roofs over 40 ft, torch-down work, alcohol over half of sales, two or more recent claims) come from plain Python rules a broker can read and disagree with, never from the model.
